## Runtime

`BrowserVideoEngine` implements the existing engine contract. @ffmpeg/ffmpeg 0.12.15 runs its own module Web Worker; @ffmpeg/core 0.12.10 is the single-thread core. `npm install` copies their ESM distributions to public/ffmpeg. Next serves these same-origin assets, avoiding CDN uploads and cross-origin worker failures. No media processing runs on Vercel Functions. WASM loads only when the user starts processing.

Precision Cut uses input-side accurate seek to decode only the preceding GOP. Fast Cut snaps target boundaries to preceding keyframes and copies compatible H.264/AAC streams; it is not frame-accurate. Ranges are half-open and limited by video-frame and audio-sample precision. H.264 yuv420p and AAC 128 kbps are written into fast-start MP4. Off uses CRF 18 / ultrafast (speed-focused, potentially larger files); High 20 / medium; Balanced 25 / medium; Smaller 30 / fast. Off still re-encodes to preserve accurate cuts; it is not lossless. Dimensions are preserved except padding an odd dimension by one pixel for H.264 compatibility. Compression can increase file size.

The source is mounted once with read-only WORKERFS, with a one-time MEMFS transfer fallback. The loaded worker and source are reused across clips and successful jobs; output temporary files are removed after each clip, and replacing a source/cancelling/unmounting disposes the retained worker. Worker termination cancels the active encode; replacing a source/clearing results/unmounting revokes preview URLs. MP4 download URLs expire after 60 seconds. Partial completed clips remain available after cancellation. ZIP bundling uses STORE, as MP4 is already compressed.

Safety caps are 256 MiB source, 500 planned clips, 512 MiB aggregate outputs, 256 MiB per ZIP. These are conservative guards, NOT benchmarked device limits. Browser OOM can still happen below them. Precision re-encoding still uses substantial CPU; long recordings may be slow. Fast Cut avoids re-encoding. ZIP packaging has its own cancellable worker and measured progress. Mobile, Safari, Firefox, VFR, unusual codecs, damaged media and long files require further validation.

## Setup and checks

Node 24 is required for dependency-free TypeScript tests. Run:

```
npm install
npm run lint
npm run typecheck
npm test
npm run test:media
npm run build
npx playwright install --with-deps chromium
npm run test:browser
```

The dependency lockfile was regenerated by the authorized GitHub Actions runner and transferred through compressed CI logs into this restricted workspace. CI uses npm ci for reproducible installs. Native FFmpeg/ffprobe and unzip are required for integration/browser checks. Playwright starts the built Next server. The browser test processes a generated 35-second MP4 into a 30-second balanced export, checks HTML video playback, downloads/probes MP4 and checks the downloaded ZIP. It must pass before claiming browser functionality verified.

- Select a generated 35-second 320×180 30fps H.264/AAC MP4, read metadata and display original preview.
- Manual trim from 1.25 to 31.25 seconds, Balanced compression, using the actual single-thread WASM Web Worker.
- Load the processed HTML video, play it and observe advancing playback time.
- Download the actual MP4 and inspect it with ffprobe: duration within 0.05s of 30s, H.264 video and AAC audio.
- Download and validate the ZIP archive.
- Split the full source into 10-second clips with compression Off and remainder Keep; download ZIP, extract four MP4s and check durations 10/10/10/5 seconds within 0.05s each.

- Start a new processing job, cancel it, and verify the cancelled state and re-enabled processing control.

### Native FFmpeg checks

Every output is 30.000s H.264/AAC; video/audio start and duration differences are below 0.05s and full decode succeeds.
